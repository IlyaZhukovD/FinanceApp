## 1. Что импортируем

Источник — страница Notion «Финансы (1)». Разобрана через Notion API 31.10.2026.

| База Notion | Где лежит | Строк | Куда в приложении |
|---|---|---|---|
| «Траты» | страница «2025» | 127 | раздел «Расходы» |
| «Траты » (с пробелом в конце) | страница «2026» | 127 | раздел «Расходы» |
| «Доход» | прямо на «Финансы (1)» | 21 (янв 2025 – сен 2026, одна строка на месяц) | раздел «Доходы» |

**Не импортируем** в v1:
- старые таблицы внутри страниц «Январь 2025» … «Апрель 2025» (другая схема:
  `Name`, `Number`, `Select`, `Text`, без месяца). Эти месяцы уже есть в базе «Траты» 2025;
  импорт обеих версий удвоил бы суммы;
- «Планируемые траты на осень 2025» — это план, а не факт;
- «Путешествия», «Инвестиции» — другая природа данных (активы — отдельное ТЗ, если нужно).

### 1.1. Схема баз «Траты»

| Колонка Notion | Тип | Как используем |
|---|---|---|
| `Name` | заголовок | комментарий ячейки (заполнен примерно у каждой 5-й строки) |
| `Number` | число, рубли, целые | сумма → `amount_minor = Number × 100` |
| `Категория` | мультиселект | категория расходов (правило для нескольких значений — 3.3) |
| `Месяц` | селект «Январь…Декабрь» (`июнь` — со строчной) | месяц периода — **основной источник** |
| `Год` | селект «2025/2026» | год периода — основной источник |
| `Date` | дата, почти всегда 1-е число | запасной источник периода |

### 1.2. Схема базы «Доход»

`Name` (всегда пустой), `Number`, `Date` (1-е число месяца). Категорий нет.

### 1.3. Что найдено в данных и требует правил

| Наблюдение | Где | Правило |
|---|---|---|
| Нет `Год` и `Date`, есть только `Месяц` (5 строк, напр. «Октябрь, дом, 19 500») | 2026 | год по умолчанию для файла (3.1) |
| Нет `Месяц` | 2026, 1 строка | берём из `Date`; нет и её — строка в «ошибки» |
| `Месяц` расходится с `Date` (`2025-03-01` / «Февраль», `2025-09-01` / «Август») | 2025, 2 строки | приоритет у `Месяц`+`Год`, строка помечается ⚠ в предпросмотре |
| Две категории в одной строке («развлечение, гидрики», 5 500) | 2025, 1 строка | 3.3 |
| Пустая строка (нет суммы и категории) | 2026, 1–2 строки | молча пропускаем, считаем в отчёте |
| Нет суммы при наличии категории | 2026 | строка в «ошибки», не импортируется |
| Нет категории при наличии суммы | 2026, 2 строки | категория «Прочее» (можно переназначить на шаге 3) |
| Дробных и отрицательных сумм нет | все | поддерживаются всё равно (сторно) |

## 2. Как сохранять файлы из Notion (инструкция для владельца)

Делается **один раз на каждую базу** (3 экспорта). Приложение берёт ZIP как есть,
распаковывать не нужно.

1. Открой базу на отдельной странице: наведи на таблицу «Траты» на странице «2026» →
   `⋯` справа от названия → **«Открыть как полную страницу»** (Open as full page).
   Экспорт встроенной таблицы со страницы-родителя потащит соседние страницы.
2. На странице базы: `⋯` в правом верхнем углу → **Экспорт** (Export).
3. Параметры:
   - Формат: **Markdown & CSV**;
   - Включить содержимое: **Всё** (Everything);
   - Подстраницы: **выключено** (Include subpages — off);
   - Файлы и изображения — не важно (лучше выключить, архив меньше).
4. **Экспортировать** → браузер скачает `ExportBlock-….zip`.
5. Переименуй и положи в одну папку, например
   `Документы\Finance\import\`:
   - `notion-траты-2025.zip`
   - `notion-траты-2026.zip`
   - `notion-доход.zip`

   Имя файла приложению не важно — тип базы оно определит по колонкам, — но так проще
   не перепутать. Год в имени (`2025`/`2026`) мастер подставит как «год по умолчанию».
6. Повтори для базы «Траты» на странице «2025» и для «Доход».

Что внутри ZIP (приложение разбирает само): иногда вложенный ZIP (`…Part-1.zip`), в нём
`Траты <id>.csv` (текущий вид) и `Траты <id>_all.csv` (все строки и колонки).
Используется **`_all.csv`**; если его нет — обычный `.csv`.
Кодировка UTF-8 (с BOM). Если хочется, можно выбрать в мастере сам CSV вместо ZIP.

> Почему не напрямую через Notion API: нужен токен интеграции и сеть, а приложение
> local-first и `NetworkMode` в v1 выключен. Импорт по API можно добавить позже тем же
> движком, поменяв только «чтение источника» (раздел 5).

## 3. Правила преобразования

### 3.1. Период
1. `Месяц` (без учёта регистра, «июнь» = «Июнь») + `Год` → `Period`.
2. Нет `Год` → год из `Date`; нет и её → **год по умолчанию** файла (берётся из имени
   файла, если там есть `20xx`, иначе текущий; меняется на шаге 1 мастера).
3. Нет `Месяц` → месяц из `Date`; нет и её → ошибка строки.
4. `Date` с временем или диапазоном (`… → …`) — берётся начало.
5. `Месяц`/`Год` противоречат `Date` → используем `Месяц`+`Год`, предупреждение ⚠.
6. Период вне `200001..210012` → ошибка строки.

Форматы `Date` в CSV зависят от языка Notion; поддерживаем:
`2026-10-01`, `October 1, 2026`, `1 октября 2026 г.`, `01.10.2026`.

### 3.2. Сумма
- Разбор через `BigDecimal`, без `Double`. Отбрасываются пробелы (в т.ч. неразрывные),
  `₽`, `руб`; запятая — десятичный разделитель, если после неё 1–2 цифры, иначе разделитель
  тысяч. Результат — копейки, `HALF_UP` не нужен (больше 2 знаков → ошибка строки).
- Сумма 0 → строка пропускается (в отчёт), ведь в приложении сумма ≠ 0 (F1.4).

### 3.3. Категория
- Ровно одно значение → оно.
- Пусто → «Прочее» (переназначается на шаге 3).
- Несколько значений → **первое** становится категорией, остальные дописываются в
  комментарий как `#гидрики`. В предпросмотре строка помечена ⚠, категорию можно сменить.
  Делить сумму между категориями не будем — нет основания для пропорции.

### 3.4. Комментарий
- `Name` непустой → комментарий. Несколько строк в одну ячейку сливаются по правилу F1.5
  (одинаковые не дублируются, разные — каждая с новой строки).
- Для доходов комментария нет.

### 3.5. Группировка
Строки группируются в ячейки `(секция, категория, период)`; на ячейку — **одна** ревизия
`op = IMPORT`, `source = IMPORT` с суммой группы (F10.1). Если ячейка уже есть в базе —
сумма прибавляется (аккумулирование F1.5), комментарий сливается.

### 3.6. Доходы
Вся база «Доход» идёт в одну категорию доходов, выбранную на шаге 3
(по умолчанию «Зарплата»). Возможность разнести по категориям — только вручную после.

## 4. Мастер импорта (UI)

Вход: меню **Файл → Импорт из Notion…**. Реализация: раздела «Настройки → Данные» пока нет,
поэтому история импортов с кнопкой «Отменить импорт» показана на шаге 1 мастера. Модальное окно,
4 шага, «Назад» на любом шаге, ничего не пишется в базу до шага 4.

**Шаг 1. Файлы.** Выбор одного или нескольких `.zip`/`.csv` (можно все три сразу).
Для каждого файла: распознанный тип («Расходы» / «Доходы» / «Не распознан»), число строк,
год по умолчанию (редактируемый), отметка «этот файл уже импортировался <дата>» (по sha256).
Тип распознаётся по колонкам: есть `Категория` → расходы; только `Name/Number/Date` → доходы.
Тип можно переключить вручную.

**Шаг 2. Колонки.** Автосопоставление по именам из 1.1/1.2; можно поправить выпадашками
(на случай, если колонку переименуют в Notion). Показываются 5 первых строк.

**Шаг 3. Категории.** Таблица «категория Notion → категория приложения» с суммой и числом
строк. Варианты для каждой: **создать новую** (по умолчанию, то же имя, цвет из палитры) /
**сопоставить с существующей** / **пропустить**. Несколько категорий Notion можно направить в
одну. Подсказки-дубли, найденные в данных: «маме» и «мама», «дом» и «на дом»,
«кикшеринг» и «самокаты» — показать значком 🔗 «похоже на…». Для доходов — выбор одной
категории. Сопоставление запоминается (`app_setting`, ключ `import.notion.categoryMap`) и
подставляется при следующем импорте.

**Шаг 4. Предпросмотр и импорт.** Сводная таблица по месяцам × секциям:
строк → ячеек → сумма; отдельные вкладки «⚠ Предупреждения», «✖ Ошибки», «Пропущено».
Итоговые суммы по месяцам сверяются глазами с Notion. Кнопка **«Импортировать»**:
1. снапшот базы `backups/Finance-<UTC>-v<schema>-pre-import.db` (`VACUUM INTO`) —
   без него импорт не стартует;
2. одна транзакция: категории + ячейки + ревизии + `sync_outbox` + запись о пакете;
3. отчёт: «Импортировано N строк в M ячеек, создано K категорий, пропущено X
   (дубли / пустые / ошибки)», кнопки «Открыть Расходы за <первый месяц>», «Отменить импорт».

**Отмена импорта**: одной кнопкой из отчёта и из «Настройки → Данные → История импорта».
Откатывает ровно этот пакет (ревизиями `UNDO`, не удалением), категории, созданные
пакетом, архивируются, если в них не осталось сумм.

## 5. Архитектура

```
core:import     (новый) чистый Kotlin, без SQL/Compose:
                ZipCsvSource → CsvReader (RFC 4180, BOM, ; или ,) →
                NotionRowParser (правила раздела 3) → ImportPlan
                ImportPlan = строки + предупреждения + ошибки + группы по ячейкам
core:domain     use-case ImportLedgerBatch(plan, categoryMapping) и UndoImportBatch(batchId);
                интерфейс ImportBatchRepository
core:data       реализация репозитория, миграция 4.sqm
feature:import  (новый) мастер, состояние шагов, контроллер
```

Чтение источника отделено от разбора: будущий импорт через Notion API даст тот же
`ImportPlan`.

### 5.1. Схема — миграция `4.sqm` (v4 → v5)

Реализация (D-27): пакет — один запуск мастера (может включать несколько файлов), а вместо
колонки `batch_id` в ревизиях связь «строка → пакет → ревизия» хранится в таблице
`import_row`. Итоговая схема — `ImportBatch.sq` и `4.sqm`. Черновик ниже оставлен для истории.

```sql
CREATE TABLE import_batch (
  id TEXT PRIMARY KEY NOT NULL,
  source TEXT NOT NULL,            -- NOTION_CSV
  file_name TEXT NOT NULL,
  file_sha256 TEXT NOT NULL,
  section TEXT NOT NULL,           -- EXPENSE | INCOME
  rows_total INTEGER NOT NULL,
  rows_imported INTEGER NOT NULL,
  cells_touched INTEGER NOT NULL,
  status TEXT NOT NULL,            -- APPLIED | UNDONE
  created_at_utc INTEGER NOT NULL,
  updated_at_utc INTEGER NOT NULL,
  row_version INTEGER NOT NULL DEFAULT 1,
  deleted_at_utc INTEGER
);
ALTER TABLE category_month_revision ADD COLUMN batch_id TEXT;  -- в конец, по правилу SPEC §6
```

### 5.2. Дедупликация (F10.2)
CSV из Notion не содержит id страниц, поэтому ключ строки:
`sha256(id базы из имени CSV | Name | Number | Date | Месяц | Год | Категория | k)`,
где `k` — порядковый номер среди полностью одинаковых строк файла.
- Повторный импорт того же или более нового экспорта: уже импортированные строки
  пропускаются («уже импортировано»), новые добавляются.
- Ограничение: строку, **изменённую** в Notion после импорта, приложение увидит как
  новую. Поэтому рекомендуемый сценарий — разовый перенос истории, дальше учёт в
  приложении. В предпросмотре такой случай не детектируется — честно пишем это в
  подсказке шага 4.
- Ключи строк хранятся в `import_row` (реализация, D-27); `idempotency_key` ревизии —
  `import:<пакет>:<ячейка>`.

## 6. Тесты

- `core:import`: golden-тесты на фикстурах — обезличенные CSV в формате Notion
  (оба языка дат, BOM, вложенный ZIP, `_all.csv` и без него), каждое правило 1.3 и 3.x
  отдельным кейсом; детерминированность `ImportPlan`.
- `core:domain`: импорт в пустую базу и поверх существующих ячеек (аккумулирование,
  слияние комментариев), повторный импорт = 0 новых строк, отмена пакета возвращает
  суммы, архивирование созданных категорий, импорт в архивную категорию запрещён.
- `core:data`: миграция 4→5 (fresh + upgrade), атомарность (сбой посреди → ничего не
  записано), `batch_id` в ревизиях.
- Ручная приёмка (`docs/manual-test-checklist.md`): три реальных экспорта владельца,
  сверка помесячных итогов приложения с Notion по 3 выбранным месяцам, повторный импорт,
  отмена.

## 7. Критерии приёмки

1. Все три ZIP из раздела 2 импортируются за один проход мастера.
2. Помесячные суммы расходов и доходов в приложении совпадают с суммами в Notion
   (с поправкой на строки из «Ошибки», которые показаны явно).
3. Повторный импорт тех же файлов не меняет ни одной суммы.
4. «Отменить импорт» возвращает базу к состоянию до импорта (кроме архивных категорий).
5. Перед импортом в `backups/` появляется снапшот.
6. `./gradlew test` зелёный.
