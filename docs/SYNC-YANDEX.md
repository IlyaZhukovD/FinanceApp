# Синхронизация через Яндекс.Диск — техническое задание (черновик v0.1)

Статус: **реализовано** (S1–S5), решения реализации — DECISIONS D-29, бэкапы — D-30.
Проверено тестами (два «компьютера» в памяти, транспорт против локального сервера с
протоколом Диска); на реальном Яндекс.Диске — после регистрации приложения (§11).
Развивает SPEC.md §7 («Готовность к будущей синхронизации») и F7.2 (`YANDEX_API`).

---

## 1. Задача и рамки

**Сценарий.** Одни и те же данные на нескольких компьютерах: несколько Windows и Mac.
Работа по очереди, не одновременно. Каждое устройство работает без сети и догоняет
остальные, когда сеть появляется. Телефона не будет.

**Что синхронизируется:** категории, ячейки «категория + месяц» с журналом правок
(расходы и доходы), счета активов и их месячные снапшоты.

**Что НЕ синхронизируется:** настройки (`settings.properties`, `app_setting`), AI-чаты
(их ещё нет), локальные бэкапы, история импорта из Notion (решение владельца, см. 10.3).

**Вне рамок:** шифрование (решение владельца: не нужно), телефон, одновременная работа
на нескольких устройствах с живым обменом, слияние двух непустых баз.

## 3. Транспорт: REST API Яндекс.Диска

Выбран API, а не папка клиента Яндекс.Диска: владелец хочет вход через браузер, и так
не нужен установленный клиент на каждом компьютере.

- **Регистрация приложения** в Яндекс OAuth с единственным правом «Доступ к папке
  приложения на Диске». Диск сам создаёт папку `Приложения/Finance`, приложение видит
  только её (адреса вида `app:/...`). Остальные файлы пользователя недоступны.
- **Вход.** Кнопка «Войти в Яндекс» открывает системный браузер со страницей Яндекс OAuth;
  после согласия Яндекс возвращает пользователя на адрес приложения
  `http://127.0.0.1:<порт>/oauth` — его на время входа слушает само приложение. Токен
  сохраняется в `SecretStore` (Windows Credential Manager / связка ключей macOS), не в
  базе и не в бэкапах. Токен Яндекса продлевается при использовании.
  - **Проверить первым делом:** принимает ли Яндекс OAuth адрес возврата на `127.0.0.1`
    с произвольным портом. Если нет — запасной вариант из документации Яндекса: код
    подтверждения, который пользователь копирует из браузера в приложение.
- **Загрузка файла** — два шага: `GET /v1/disk/resources/upload?path=...` даёт ссылку,
  затем `PUT` по ссылке (живёт 30 минут). Скачивание — так же через `/download`.
- **Ошибки API** и что видит пользователь: 401 — «войдите снова»; 429 — повтор с паузой;
  423 — «Яндекс временно запретил загрузку (лимит трафика)»; 507 — «на Диске нет места»;
  нет сети — тихо отложить до следующей попытки.
- Доступ — через интерфейс `SyncTransport` в `core:domain`; реализация на Ktor в
  `core:network`. Тесты домена работают с транспортом-фейком в памяти.

## 4. Что лежит на Диске

Рабочая база SQLite на Диск **не кладётся**: облако не умеет сливать базы, а копия,
снятая посреди записи, может оказаться битой. На Диске — журнал изменений, по папке на
устройство. Каждый файл пишет только одно устройство и больше никогда его не меняет,
поэтому конфликтов на уровне файлов не бывает.

```
Приложения/Finance/
  sync.json                         формат хранилища: {"format": 1, "createdAtUtc": ...}
  devices/
    <device_id>/
      device.json                   имя («Ноутбук Ильи»), ОС, версия приложения и схемы,
                                    номер последнего пакета
      changes-000001.jsonl          пакет изменений: по строке на изменение
      changes-000002.jsonl
      ...
```

- `device_id` — UUID, создаётся при первом включении синхронизации, хранится в
  `sync_state`.
- **Отправка:** всё, что накопилось в `sync_outbox` со статусом `pending`, уходит одним
  новым файлом `changes-<следующий номер>.jsonl`; затем обновляется `device.json`, и
  записи outbox помечаются отправленными. Если загрузка оборвалась — повтор с тем же
  номером файла (`overwrite=true`), содержимое детерминировано.
- **Получение:** для каждого чужого устройства в `sync_state` хранится номер последнего
  применённого пакета; скачиваются и применяются только более новые файлы, по порядку.
- Сжатия журнала нет (решение владельца). Объём оценочно — десятки килобайт в месяц.

## 5. Модель изменений и правила слияния

Одна строка `.jsonl` — одно изменение: тип сущности, id, операция, поля, `updated_at_utc`,
`row_version`, `device_id`. Применение идемпотентно: уже применённое изменение (по
`change_id`) пропускается.

| Сущность | Что передаётся | Как сливается |
|---|---|---|
| Ячейка «категория + месяц» | **ревизии** (журнал правок), а не итог | значение ячейки = последовательное применение всех ревизий по порядку `(created_at_utc, device_id, change_id)`: прибавки (`CREATE`, `ADD`, `IMPORT`, `DUPLICATE`) складываются, явная правка (`SET_AMOUNT`, `SET_COMMENT`) и удаление/восстановление перезаписывают |
| Ячейка: ключ | `(category_id, period)` | две ячейки одного ключа, созданные на разных устройствах, — одна ячейка; остаётся id, меньший по строке, ревизии второй переносятся на неё |
| Категория | вся запись | поля — кто последний, тот и прав; **одинаковое имя в одной секции** (без учёта регистра) → категории сливаются автоматически, ячейки переносятся на одну (как F3.3) |
| Счёт актива | вся запись | кто последний, тот и прав |
| Снапшот актива | вся запись, ключ `(account_id, period)` | кто последний, тот и прав |
| Удаление | tombstone (`deleted_at_utc`) | обычная правка: кто последний, тот и прав |

«Кто последний» = больше `updated_at_utc`, при равенстве — больше `row_version`, затем
больше `device_id` (строкой). Время устройств может расходиться — владелец это принял.

**Что нужно доделать в данных** (сейчас в `sync_outbox` пишутся только ячейки и активы):
- писать в outbox категории и ревизии ячеек, в той же транзакции, что и изменение;
- таблица соответствия id при слиянии категорий и ячеек (`sync_alias`: чужой id → наш);
- `device_id` и курсоры в `sync_state`.
Это миграция схемы v5 → v6.

## 6. Подключение устройств

1. **Первое устройство:** «Настройки → Синхронизация → Войти в Яндекс». Если на Диске
   пусто — создаётся `sync.json`, и вся текущая база уходит первым пакетом.
2. **Следующее устройство:** вход тем же аккаунтом. Если локальная база **пустая** — всё
   скачивается с Диска. Если **не пустая** — синхронизация не включается: приложение
   объясняет, что второе устройство подключается с пустой базой, и предлагает создать
   пустую базу (это уже есть в настройках) — решение владельца «второе устройство будет
   пустым».

## 7. Когда синхронизируется

- При запуске, при закрытии окна, раз в N минут, пока приложение открыто (см. вопрос
  10.1), и по кнопке «Синхронизировать» в сайдбаре (`Ctrl+S` / `⌘S`).
- Только при включённой синхронизации в настройках и `NetworkMode.ON` (SPEC F9.3).
- Порядок: сначала получить чужие изменения, потом отправить свои.
- Статус в сайдбаре (SPEC F7.9): «Синхронизировано 5 мин назад» / «Есть неотправленные
  изменения» / «Нет сети» / «Ошибка — подробнее».

## 8. Ошибки и защита данных

- **Папка на Диске удалена, `sync.json` пропал или файл пакета не читается** —
  синхронизация останавливается и показывает, что случилось, с выбором: «Создать
  хранилище заново из этого компьютера» или «Отключить синхронизацию». Само ничего не
  пересоздаёт (решение владельца).
- **Перед применением чужих изменений** — снапшот базы в `backups/`, как перед импортом.
  Применение пакета — одна транзакция: либо весь, либо ничего.
- **Сборка из исходников** (`app.finance-dev`, D-28) по умолчанию синхронизацию не
  включает; если включить вручную — работает с отдельной папкой `Приложения/Finance/dev`.
- **Разные версии приложения.** В `sync.json` и `device.json` хранятся версия формата и
  версия схемы базы. Если на Диске уже есть пакеты от более новой версии, устройство
  не синхронизируется: показывает «Обновите Finance на этом компьютере — на другом стоит
  более новая версия» и не отправляет и не принимает изменения до обновления.

2. ~~Разные версии приложения~~ — решено: старая версия не синхронизируется до обновления (§8).

## 11. Как включить (один раз)

1. Откройте https://oauth.yandex.ru/client/new, войдите своим аккаунтом Яндекса.
2. Название — например «Finance», платформа — **«Веб-сервисы»**.
3. Redirect URI — оба адреса:
   - `http://127.0.0.1:53682/oauth` (возврат в приложение после входа в браузере);
   - `https://oauth.yandex.ru/verification_code` (запасной вход кодом).
4. Доступы: **«Яндекс.Диск REST API» → «Доступ к папке приложения на Диске»**
   (`cloud_api:disk.app_folder`). Других прав не нужно.
5. Создайте приложение и скопируйте **ClientID**.
6. В Finance: «Настройки» → «Синхронизация через Яндекс.Диск» → вставьте Client ID →
   «Войти через браузер» → подтвердите доступ → «Включить синхронизацию».
7. На следующем компьютере: тот же Client ID и вход, база — **пустая** (Настройки → База
   данных → «Добавить базу…» или свежая установка), затем «Включить синхронизацию».

Данные лежат на Диске в «Приложения/Finance» (сборка для разработки — в подпапке `dev`).
