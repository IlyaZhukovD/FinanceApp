# Finance

Десктоп-приложение для личного учёта финансов: расходы, доходы и активы
с гранулярностью «месяц + год», аналитика и графики, бэкап в папку Яндекс.Диска
и AI-разбор показателей через OpenRouter.

Офлайн, без сервера и без логина. macOS и Windows. Только светлая тема.

- Полное ТЗ: [`docs/SPEC.md`](docs/SPEC.md)
- Принятые решения и их причины: [`docs/DECISIONS.md`](docs/DECISIONS.md)

## Стек

Kotlin 2.4.20 · Compose Multiplatform 1.12.0 · SQLite через SQLDelight 2.3.2 · JVM target 21.

Локально данные лежат в SQLite (один файл), а не в PostgreSQL: причины — в
`docs/DECISIONS.md`, D-01. PostgreSQL остаётся целевой БД будущей серверной части.

В `app:desktop` подключён `kotlinx-coroutines-swing`: `Dispatchers.Main` на десктопе —
это Swing EDT, и без этого артефакта окно падает в рантайме с «Module with the Main
dispatcher is missing», хотя компиляция и все тесты проходят. Найдено дымовым прогоном.

```
core/charts       графики на Canvas: StackedBar, GroupedBar, Line, Combo, Donut + hover-тултипы

core/network      OpenRouter и будущий backend API
core/backup       снапшоты, checksum, retention, восстановление
feature/*         ledger (общий движок расходов и доходов), expenses, income,
                  assets, analytics, categories (общий справочник), ai, settings
app/desktop       точка входа, граф зависимостей, окно, упаковка
docs/             SPEC.md, DECISIONS.md
.tools/           локально скачанный Gradle (не коммитится)
```

Модули добавляются в `settings.gradle.kts` по мере реализации; сейчас подключены
`core:model`, `core:domain`, `core:analytics`, `core:data`, `core:charts`, `core:ui`,
`feature:ledger`, `feature:expenses`, `feature:income`, `feature:assets`,
`feature:analytics`, `feature:categories`, `feature:settings`, `app:desktop`.
Модуля `feature:categories` в целевом списке SPEC.md §4 нет — он добавлен решением D-18,
потому что справочник категорий нужен трём разделам сразу, а `core:ui` обязан оставаться
слоем представления без доступа к домену.
Экраны расходов и доходов — это один модуль `feature:ledger` с разными секциями
(`docs/SPEC.md`, F2.2; `docs/DECISIONS.md`, D-12), а `feature:expenses` и `feature:income`
содержат только точки входа разделов. Активы — отдельный `feature:assets` со своим
контроллером: единица учёта там снапшот счёта, а не ячейка «категория + месяц» (D-14).
Аналитика разбита на `core:analytics` (чистые расчёты серий и метрик, golden-тесты) и
`feature:analytics` (read-only контроллер и экран) — F6.4, D-15. Одноимённые модули в разных
слоях допустимы: `group` формируется из пути проекта, иначе Gradle считает их одним
артефактом и подменяет проект проектом (D-16).

## Где живут данные пользователя

- macOS: `~/Library/Application Support/app.finance/`
- Windows: `%APPDATA%\app.finance\`

Внутри: `finance.db` (основная база), другие базы из списка настроек (например
`finance-test.db`), `settings.properties`, `backups/`, `logs/`. БД, бэкапы и логи
исключены из системы контроля версий — финансовые данные не должны попадать в репозиторий.

`settings.properties` — список баз и активная из них. Файл намеренно лежит ВНЕ баз данных:
выбор базы не может зависеть от её содержимого. Формат текстовый (UTF-8,
`java.util.Properties`), поэтому файл можно поправить руками при закрытом приложении — это
аварийный выход, если база не открывается (D-18). Удаление базы из списка не удаляет файл
на диске, а активную и единственную базу убрать из списка нельзя.

## Ключевые соглашения

- **Деньги** — целые копейки (`Money.minor: Long`), плавающая точка запрещена.
- **Период** — `year * 100 + month` (`202602`), только UTC-время в БД.
- **Ячейка «категория + месяц»** — единица учёта: повторный ввод суммы в ту же категорию
  того же месяца аккумулируется в существующую строку, а не создаёт новую. Каждое
  изменение пишется в журнал ревизий, поэтому ввод обратим.
- **Удаление** — soft delete (`deleted_at_utc`); для категорий это архивация (F3.2):
  категория исчезает из пикеров, но её суммы и история остаются.
- **Настройки и выбор базы** — `settings.properties` вне баз данных; смена базы собирает
  новый граф зависимостей без перезапуска приложения, а прежнее подключение закрывается
  только после успешного открытия нового (`docs/DECISIONS.md`, D-18).
- **SQLite** — WAL и контроль внешних ключей задаются свойствами соединения, а не разовым
  `PRAGMA` после открытия (`docs/DECISIONS.md`, D-11).
- **Секреты** (API-ключ OpenRouter) хранятся только в `SecretStore`, никогда в БД
  и в бэкапах.
